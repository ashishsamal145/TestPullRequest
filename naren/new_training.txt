Explanation:---------------------------------------------------------------------------------------------

Short summary first: this is an Azure DevOps multi-stage pipeline that creates a timestamp, runs a dev training job (by applying a Kubernetes Job manifest template into a dev AKS cluster), and — if the earlier steps succeed and the build source is main/master — repeats the same in prod. Below I walk through each line/statement and explain what it does.

Final notes, gotchas and tips

Trigger path vs filename: The trigger.paths.include references training-pipeline-azure.yml (lower-case .yml) — make sure the actual filename matches, otherwise triggers won't fire.

Cron timezone: Cron is specified in UTC. The display says EST — verify DST handling and intended zone.

Artifacts: The scratchpad artifact produced in SetTimestamp is how the timestamp is passed to downstream jobs — make sure the deployTrainJobManifest.yml template expects to find the timestamp (it usually downloads artifacts inside).

Templates: The heavy lifting (kubectl, secret/configmap creation, kubectl apply) is inside pipeline-templates/deployTrainJobManifest.yml. That template must accept the parameters shown and create secrets/configmaps and apply the job manifest jobManifest.

Conditional Prod deploy: The ProdTrain stage only runs if the source pipeline/build came from main or master — this prevents accidental production runs from feature branches.

Timeouts: All jobs have a 300-minute timeout — training jobs can run long; adjust if needed.

#  deployTrainJobManifest.yaml

# job variables from pipeline
#        $(jobName)
#        $(jobManifest)

parameters:
  DEPLOYMENT_SERVICE_CONNECTION: 'NOT_DEFINE'
  NAMESPACE: 'NOT_DEFINE'
  AZURE_STORAGE_ACCOUNT: 'NOT_DEFINE'
  AZURE_STORAGE_ACCOUNT_SAS_TOKEN: 'NOT_DEFINE'
  ARTIFACT_NAME: 'NOT_DEFINE'
  AZURE_MODEL2_OUTPUT_CONTAINER: 'NOT_DEFINE'
  AZURE_STORAGE_WORKSPACE_CONTAINER: 'NOT_DEFINE'

steps:  
          - download: current
            artifact: scratchpad
          - bash: |
              TRAIN_TIMESTAMP=$(<'$(Pipeline.Workspace)/scratchpad/TrainTimestamp.txt') 
              # expose timestamp in build variable
              echo "##vso[task.setvariable variable=TrainTimestamp;]${TRAIN_TIMESTAMP}"
            
            displayName: 'Read training timestamp'

          - bash: |
              echo "TrainTimestamp is [$(TrainTimestamp)]"   
            displayName: 'Show results of train timestamp'
          
          - template: updateInstalls.yml  # Template reference

          - task: AzureCLI@2
            displayName: Get storage account name
            inputs:
              azureSubscription: '${{parameters.DEPLOYMENT_SERVICE_CONNECTION}}' 
              scriptType: 'pscore'
              scriptLocation: 'inlineScript'
              addSpnToEnvironment: true
              inlineScript: |

                 gci -recurse * | select directory, name

                 gci env: |  where Name -notmatch token | format-table -wrap

                 write-output "Image name is $(TrainImageName):$(resources.pipeline.sourcetrainbuild.runName)"
                 
                 $storageAccounts=(az resource list -o json | convertfrom-json) | where type -eq "Microsoft.Storage/storageAccounts"
                 $storageAccounts | format-table
                 $AzureStorageAccount='${{parameters.AZURE_STORAGE_ACCOUNT}}'
                 # if a specific storage account was not specified, take the storage account from the service connection
                 if ($AzureStorageAccount -eq 'NOT_DEFINE') {
                    $AzureStorageAccount = ($storageAccounts | select -First 1).name                   
                    }
                 Write-Host "##vso[task.setvariable variable=AzureStorageAccount;]$AzureStorageAccount"
                 Write-host "using storage account $AzureStorageAccount"

          - powershell: |
              $AZURE_STORAGE_OUTPUT_CONTAINER='${{parameters.AZURE_MODEL2_OUTPUT_CONTAINER}}' 
              $AZURE_STORAGE_WORKSPACE_CONTAINER='${{parameters.AZURE_STORAGE_WORKSPACE_CONTAINER}}'

              write-output 'storage account is $(AzureStorageAccount)'
              write-output "AZURE_STORAGE_OUTPUT_CONTAINER=$AZURE_STORAGE_OUTPUT_CONTAINER"
              write-output "AZURE_STORAGE_WORKSPACE_CONTAINER=$AZURE_STORAGE_WORKSPACE_CONTAINER "

              # set up storage containers
              $context = New-AzStorageContext -StorageAccountName '$(AzureStorageAccount)' -SasToken '${{parameters.AZURE_STORAGE_ACCOUNT_SAS_TOKEN}}'
              $contents = Get-AZStorageContainer -context $context
            
              if (-not ( $contents | where name -eq $AZURE_STORAGE_OUTPUT_CONTAINER)) {
                 New-AzStorageContainer -context $context -name $AZURE_STORAGE_OUTPUT_CONTAINER  -Permission Container
              }
              if (-not ( $contents | where name -eq $AZURE_STORAGE_WORKSPACE_CONTAINER)) {
                New-AzStorageContainer -context $context -name $AZURE_STORAGE_WORKSPACE_CONTAINER -Permission Container
              }
            
              # create a manifest which reflects the correct build

              (gc 'deployment/kubernetes/$(jobManifest)').replace('{TRAIN_TIMESTAMP}','$(TrainTimestamp)').replace('$(TrainImageName):latest','$(TrainImageName):$(resources.pipeline.sourcetrainbuild.runName)') `
                  > $(Build.ArtifactStagingDirectory)/$(jobManifest)
            
              gc $(Build.ArtifactStagingDirectory)/$(jobManifest)

            displayName: 'Prepare to run training through aks'

          - task: PowerShell@2
            displayName: 'Check Environment variables'
            inputs:
                targetType: 'inline'
                script: |
                  # Write your PowerShell commands here.
                      
                  gci env: | format-table -wrap
                  gci  -recurse | select fullname
          
          - task: AzureCLI@2
            displayName: Get aks cluster name
            inputs:
              azureSubscription: '${{parameters.DEPLOYMENT_SERVICE_CONNECTION}}'
              scriptType: 'pscore'
              scriptLocation: 'inlineScript'
              addSpnToEnvironment: true
              inlineScript: |
                # we arent using az aks list anymore as it's not working consistently in al environments
                $resources = az resource list -o json | convertfrom-json       
                $aksList = $resources | where 'type' -eq 'Microsoft.ContainerService/managedClusters'
                $aksList | format-table
                $aksName='$(aksName)'
                $aksResourceGroup='$(aksResourceGroup)'
                # use specific aks is named, otherwise derive from service connection permissions
                if (('set in script' -eq $aksResourceGroup) -or ('set in script' -eq $aksName))
                {
                  write-host "Setting aks from service connection environment"
                  $aksName = ($aksList | select -First 1).name
                  $aksResourceGroup= ($aksList | select -First 1).resourceGroup
                }
                Write-host "using aks $aksName resource group $aksResourceGroup "
                Write-Host "##vso[task.setvariable variable=aksName;]$aksName"
                Write-Host "##vso[task.setvariable variable=aksResourceGroup;]$aksResourceGroup"  
          
          - task: AzureCLI@2
            displayName: use kubelogin to connect
            inputs:
              azureSubscription: '${{parameters.DEPLOYMENT_SERVICE_CONNECTION}}'
              scriptType: 'bash'
              scriptLocation: 'inlineScript'
              inlineScript: |

                Write-host "using aks $(aksName) resource group $(aksResourceGroup)"
                rm -f ".kube/config" &&  az aks get-credentials --resource-group '$(aksResourceGroup)' \
                      --name '$(aksName)' \
                      --overwrite-existing 

                kubelogin convert-kubeconfig -l azurecli

                kubectl config set-context --current --namespace '${{parameters.NAMESPACE}}'

                kubectl get pods 2>&1

          - task: AzureCLI@2
            displayName: apply manifest
            inputs:
              azureSubscription: '${{parameters.DEPLOYMENT_SERVICE_CONNECTION}}'
              scriptType: 'pscore'
              powerShellErrorActionPreference: continue
              scriptLocation: 'inlineScript'
              inlineScript: |
                
                kubectl delete secret         $(jobName)-secret  2>&1 | Out-Null
                kubectl create secret generic $(jobName)-secret --from-literal=AZURE_SAS_TOKEN='${{parameters.AZURE_STORAGE_ACCOUNT_SAS_TOKEN}}'

                kubectl delete configmap      $(jobName)-config  2>&1 | Out-Null
                kubectl create configmap      $(jobName)-config --from-literal=AZURE_STORAGE_ACCOUNT=$(AzureStorageAccount) `
                                                                    --from-literal=WORKSPACE=azure `
                                                                    --from-literal=AZURE_MODEL2_OUTPUT_CONTAINER=${{parameters.AZURE_MODEL2_OUTPUT_CONTAINER}} `
                                                                    --from-literal=AZURE_STORAGE_WORKSPACE_CONTAINER=${{parameters.AZURE_STORAGE_WORKSPACE_CONTAINER}}

                # because this is a job, not a deployment, we do not have to do the "kubectl rollout restart"
                kubectl apply -f  $(Build.ArtifactStagingDirectory)/$(jobManifest)
              
                # outputFormat: yaml
          - task: AzureCLI@2
            displayName: 'Check job progress'
            inputs:
              azureSubscription: '${{parameters.DEPLOYMENT_SERVICE_CONNECTION}}'
              scriptType: 'pscore'
              powerShellErrorActionPreference: continue
              scriptLocation: 'inlineScript'
              inlineScript: |
                # this step replaces the "wait" function in the kubernetes task, which is not
                # working properly for extremely long runnign jobs..
                write-host "kubernetes resources available:"

                #for the logs
                kubectl get pods  2>&1 
                kubectl get jobs  2>&1
                kubectl get services  2>&1

                # there may be more than one job, scope to just the one this pipeline cares about
                $jobname = "$(jobName)-sequenced-job-$(TrainTimestamp)"
                
                  try {
                      $podSpec = kubectl get pods --selector=job-name=$jobname  -o json 2> $null | convertfrom-json
                      $podname = $podspec.items[0].metadata.name
                  }  
                      catch {}
                
                $completionTime=$null
                $logs=""
                $Failed = $false
                while (-not $failed -and $podName -and -not $completionTime) {
                
                  $jobSpec = kubectl get jobs  --selector=job-name=$jobname  -o json 2> $null | convertfrom-json

Notes & gotchas (useful context)
Init container does the training: That’s intentional here. If the training fails, the init container fails and the main container never starts, so the Job won’t reach “Succeeded”. Your pipeline step that monitors the Job will see this and fail appropriately.

GPU nodes: You’re scheduling onto GPU-tainted nodes via tolerations + nodeSelector. If you intend to actually use GPU, you typically also request them, e.g.:

yaml
Copy code
resources:
  limits:
    nvidia.com/gpu: 1
(Otherwise you’re just landing on GPU nodes without reserving a GPU device.)

Image tag replacement: Your pipeline replaces :latest with a CI build tag so each run uses a pinned image. Make sure the string you replace matches the manifest. If your pipeline replaces $(TrainImageName):latest but the manifest uses a full registry path, ensure $(TrainImageName) includes the registry path or adjust the replacement target accordingly.

ttlSecondsAfterFinished: Requires the TTL controller (it’s been GA in K8s for a while). It cleans up finished Jobs/Pods 3600s (1h) after completion—keeps the cluster tidy.

Cron option: If you convert to a CronJob, uncomment kind: CronJob, add spec.schedule, and move the Pod template under spec.jobTemplate.spec.template. concurrencyPolicy: Forbid is a good choice to avoid overlapping runs.
