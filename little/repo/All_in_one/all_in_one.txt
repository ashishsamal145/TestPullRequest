Key gotchas & improvements

RWX vs managed-premium: Azure Managed Disks don’t support ReadWriteMany.

If you must use Managed Disk: change to accessModes: [ReadWriteOnce]. (You already run replicas: 1, so it’s fine.)

PodDisruptionBudget / Liveness/Readiness: For production, add probes and (optionally) a PDB if you later scale or need maintenance safety.

              #  value: "202308010500"
              value: "{TRAIN_TIMESTAMP}"
            - name: M3_TRAIN_TIMESTAMP
              # value: "202308162057"
              value: "{M3_TRAIN_TIMESTAMP}"
            - name: M4_TRAIN_TIMESTAMP
              # value: "202308162005"
              value: "{M4_TRAIN_TIMESTAMP}"
            volumeMounts:
            - mountPath: /persist
              name: scoring-data

Gotchas & suggestions (helpful notes)

Many kubectl/az commands assume agent has required CLI tools and auth installed — the included updateInstalls.yml is meant to ensure that.

Some PowerShell variables used in the poll loop are referenced before they are guaranteed to exist (e.g., $pods, $job). PowerShell is forgiving, but that can make the script brittle in some agent environments. Consider tightening:

explicitly set $pods = kubectl get pods ... before referencing,

verify $jobSpec exists before referencing $jobspec.items[0].

The script uses Write-Host "##vso[task.setvariable ...]" to set pipeline variables; this is the correct way to propagate values to later steps.

Consider adding explicit backoffLimit or activeDeadlineSeconds to Job manifests so jobs don’t retry forever or hang.

Be cautious with echoing environment in logs — ensure no secrets are printed (they attempted to filter -notmatch token, but secret names can vary).

Practical notes & gotchas

Artifact availability: scratchpad/TrainTimestamp.txt must exist in the scratchpad artifact or the initial read will fail.

Placeholder replacement: The script replaces $(TrainImageName):latest with the build run name — ensure the manifest text matches the pattern exactly.

Variable consistency: Steps set pipeline variables with ##vso[task.setvariable...] so later steps use $(AzureStorageAccount) etc. Make sure variable names match exactly.

Robustness of poll loop: The polling logic references $pods and $job in some places without explicit assignment; it works in many environments but can be brittle. Consider making the pod/job retrieval lines more defensive.

Secrets in logs: The script prints environments and manifests — ensure SAS tokens or secrets are never accidentally echoed (the script tries to filter token but be cautious).

👉 This is just for logging (printing the account name), not for real execution.

3. if (-not $dryrun) { Start-AzStorageBlobCopy … }

      If $dryrun is false or not set, then it actually executes the copy.

      If $dryrun is true, it only logs and skips the copy.

4. Start-AzStorageBlobCopy …

      This cmdlet triggers an asynchronous copy of a blob from one storage account/container to another.

      Key params:

        -SrcContainer $_.BlobClient.BlobContainerName → source container name

        -SrcBlob $_.Name → source blob name (file)

        -DestContainer $_.BlobClient.BlobContainerName → destination container (same name as source here)

        -DestBlob $_.Name → destination blob (same file name)

        -Context $contextFrom → source account connection

        -DestContext $contextTo → destination account connection

        -Force → overwrite if the blob already exists

So it’s literally doing:
👉 “Copy this blob from Prod → Extract, keeping the same container name and file name.”

✅ In plain words

    For every blob that was modified in the last 24 hours:

      Log the copy command that would run (helpful for debugging).

      If not in dry-run mode → actually perform the blob copy from $contextFrom (Prod) to $contextTo (Extract).

# clean any files greater than the specified number of days old from extract
$daysToKeep = "$(daysToKeep)"
if ($daysToKeep -ne "") {
  $blobs=@()
  Get-AzStorageContainer -context $contextTo | % { 
          $blobs += Get-AzStorageBlob -Container $_.Name -Context $contextTo
  }
  write-host "found files on $contextTo.StorageAccountName"
  $blobs | select -expand BlobClient | Out-String | Write-host
  $old = $blobs | ?{ ($_.LastModified -lt  $([DateTime]::Now.AddDays(-$daysToKeep))) } 
  write-host "Removing files more than $(daysToKeep) days old"
  $old | select -expand BlobClient | Out-String | Write-host
  if (-not $dryrun) {
    $old | Remove-AzStorageBlob -context $contextTo
  }
}


📌 Retention cleanup logic:

Reads $daysToKeep from pipeline variables.

Lists all blobs in Extract.

Finds old blobs older than $daysToKeep.

Logs them and deletes them from Extract (unless $dryrun is set).


Step by Step

1. $daysToKeep = "$(daysToKeep)"

    $(daysToKeep) is an Azure DevOps pipeline variable.

    This sets how many days’ worth of blobs should be kept in the Extract account.

    Example: if daysToKeep = 7, then files older than 7 days will be deleted.

2. if ($daysToKeep -ne "") { … }

    Only run cleanup if the variable was actually defined.

    -ne "" means “not equal to empty string.”

    So if no value is set → skip cleanup.

3. Build a full blob list in Extract

      $blobs=@()
      Get-AzStorageContainer -context $contextTo | % { 
              $blobs += Get-AzStorageBlob -Container $_.Name -Context $contextTo
      }


      Starts with an empty array $blobs.

      Loops through every container in the Extract account ($contextTo).

      For each container, retrieves all blobs (Get-AzStorageBlob) and appends them to $blobs.

      👉 At the end, $blobs = every blob in Extract across all containers.                  

4. Log what was found
      write-host "found files on $contextTo.StorageAccountName"
      $blobs | select -expand BlobClient | Out-String | Write-host


      Prints which files were found, for visibility in the pipeline logs. 

5. Filter old blobs
      $old = $blobs | ?{ ($_.LastModified -lt  $([DateTime]::Now.AddDays(-$daysToKeep))) }


      ?{} = Where-Object filter.

      For each blob:

$.LastModified → when it was last updated.

      [DateTime]::Now.AddDays(-$daysToKeep) → cutoff timestamp (e.g., 7 days ago).

      -lt = “less than.”

      So $old = all blobs older than $daysToKeep days.            

6. Log which files are being removed

      write-host "Removing files more than $(daysToKeep) days old"
      $old | select -expand BlobClient | Out-String | Write-host

7. Actually delete them (if not dry run)

      }


      If $dryrun = false → delete old blobs from Extract storage.

      If $dryrun = true → only logs, no deletion happens.

✅ In plain words

This block says:

👉 “Look at all blobs in the Extract storage account. If they are older than $daysToKeep days, delete them (unless we’re in dry-run mode).”

Function Get-AzBlobList {
        [cmdletbinding()]
        Param (
        $context 
        )


        $contents = Get-AzStorageContainer -context $context
        $allContents = @()
        foreach ($storageContainer in $contents) {
                $blobContents = Get-AzStorageBlob -context $context -container $storageContainer.name
                foreach ($blob in $blobContents) {
                        $allContents += [PSCustomObject] @{
                                AccountName =   $StorageAccountName
                                ContainerName = $storageContainer.name
                                BlobName =          $blob.Name             
                                BlobType =      $blob.BlobType
                                Length =        $blob.Length  
                                ContentType =   $blob.ContentType              
                                LastModified =  $blob.LastModified    
                                AccessTier =    $blob.AccessTier
                                SnapshotTime =  $blob.SnapshotTime             
                                IsDeleted =     $blob.IsDeleted
                                VersionId =     $blob.VersionId
                        }
                }
        }

        return $allContents
}

Function Check-StorageContainerPresenceWithoutActualTest {
    [cmdletbinding()]
    Param (
        $list,
        $context, 
        [string] $container,
        [string] $blob,
        [DateTime] $LastModifiedSince
    )
    
    $nameAndDateConstrainedList = $list | Where-Object { ($_.ContainerName -eq $container) -and ($_.blobName -like $blob) -and ($_.LastModified -gt $LastModifiedSince) }
    return ($nameAndDateConstrainedList.count -gt 0)
}


Function Test-StorageContainerPresence {
        [cmdletbinding()]
        Param (
        $list,
        $context, 
        [string] $container,
        [string] $blob,
        [string] $desiredColumns = 'yes',
        [DateTime] $LastModifiedSince
        )

        $nameConstrainedList = @($list  | ?{ ( $_.ContainerName -eq  "$container") -and ( $_.blobName -like  "$blob" ) } )
    $lastConstrainedEntry = $nameConstrainedList | Sort-Object LastModified -Descending | select-object -first 1

        Describe "Container $container has a blob $blob which is not empty and has been updated" {
                It "Container $container Blob $blob exists" {
                        $nameConstrainedList.Count | should BeGreaterThan 0 
                }
                
                It "Container $container Blob $blob is of length > 0" {
                        $lastConstrainedEntry.Length | should BeGreaterThan 0  
                }
                
                It "Container $container Blob $blob is not deleted" {
                        $lastConstrainedEntry.IsDeleted | should Be False  
                }
        
                if ($LastModifiedSince) {

                        $hoursSince = [math]::Round(([DateTime]::Now - $LastModifiedSince ).TotalHours)     
            
                        It "Container $container Blob $blob has been updated in the past $hoursSince hours" {
                                        $lastConstrainedEntry.LastModified | should  BeGreaterThan $LastModifiedSince  
            }
                }



        if (("$blob" -match ".csv") -and ($desiredColumns) -and ($lastConstrainedEntry)) {

                        $tmp = New-TemporaryFile

                        $testBlobContent = Get-AzStorageBlobContent -context $context -container $lastConstrainedEntry.ContainerName -blob $lastConstrainedEntry.blobName -Destination $tmp.name -force

                        $truncatedtmp = New-TemporaryFile

                        # csv files can be safely truncated, and this REALLY speeds up processing
                        # we run this twice so column names don't get trimmed for "not having contents" 
                        $content =  @(Get-Content $tmp.name -first 1)
                        $content += @(Get-Content $tmp.name -first 1)
                        $content | Set-Content $truncatedtmp.name

                        $blobcsv = import-csv $truncatedtmp.name

                        if ($blobcsv) {
                                $blobCsvColumns = ($blobcsv | Get-Member -MemberType Properties | Select-Object -ExpandProperty Name | Select-Object -Unique | %{"`'$_`'"})
                                $BlobCsvColumnNames = [string]::Join(", ", $blobCsvColumns)
                        }

                        $lastConstrainedEntry | Add-Member -NotePropertyName CsvColumnNames -NotePropertyValue $BlobCsvColumnNames -force

                        It "Container $container blob $($lastConstrainedEntry.blobName) has column count $($blobCsvColumns.count) should be greater than 0" {
                                $($blobCsvColumns.count) | should BeGreaterThan 0  
                        }

                        It "Container $container blob $($lastConstrainedEntry.blobName) has column names: { $($blobCsvColumnNames) } should not be empty" {
                                $($blobCsvColumnNames) | should not BeNullOrEmpty  
                        }
                        
                        del $tmp.Name
                        del $truncatedtmp.name
                }

        }
    
    write-verbose "$lastConstrainedEntry"
    
        return $lastConstrainedEntry
}

Final notes, gotchas and tips

Trigger path vs filename: The trigger.paths.include references training-pipeline-azure.yml (lower-case .yml) — make sure the actual filename matches, otherwise triggers won't fire.

Cron timezone: Cron is specified in UTC. The display says EST — verify DST handling and intended zone.

Artifacts: The scratchpad artifact produced in SetTimestamp is how the timestamp is passed to downstream jobs — make sure the deployTrainJobManifest.yml template expects to find the timestamp (it usually downloads artifacts inside).

Templates: The heavy lifting (kubectl, secret/configmap creation, kubectl apply) is inside pipeline-templates/deployTrainJobManifest.yml. That template must accept the parameters shown and create secrets/configmaps and apply the job manifest jobManifest.

Conditional Prod deploy: The ProdTrain stage only runs if the source pipeline/build came from main or master — this prevents accidental production runs from feature branches.

Timeouts: All jobs have a 300-minute timeout — training jobs can run long; adjust if needed.

🔎 High-Level Summary

These YAML and shell script files together implement an Azure DevOps CI/CD pipeline for a Revenue Prediction system that:

Prepares environments

Installs required tools (zip, helm, kubelogin, Azure PowerShell modules).

Cleans up Docker images on build agents when needed.

Creates training jobs for machine learning models (M1, M2, M3, M4)

Each training pipeline (training-pipeline-azure.yaml, m3-training-pipeline-azure.yaml, m4-training-pipeline-azure.yaml)

Sets a timestamp to tag training runs.

Runs a Dev AKS job that generates training data and stores results in Azure Blob Storage.

If successful, conditionally runs a Prod AKS job for official production training.

Uses deployTrainJobManifest.yml (not shown but referenced) to deploy a Kubernetes Job manifest to AKS.

Handles artifacts and configuration

Passes variables (like timestamp, storage account, SAS tokens, job manifest) between stages.

Publishes and downloads artifacts (scratchpad timestamp files, training results).

Automates scheduled runs

Quarterly cron schedules trigger retraining on master automatically.

Pipelines also trigger from upstream build pipelines (e.g., model training images being rebuilt).

Generates Excel outputs via APIs

Scripts (dev.create-excel-files.sh, prod.create-excel-files.sh)

Call internal APIs (/api/excel) with different business units (BUs) and sub-units.

Automates the creation of Excel-based reports in dev and prod environments.

Deployment & Job execution flow

YAML pipelines orchestrate job execution on Kubernetes (AKS).

They mount secrets and parameters (service connections, SAS tokens, namespaces).

Jobs run the actual training containers (revenue-prediction-mX-train) to process data.

📌 In Plain Words

This is a full CI/CD system for ML model training and report generation.

Developers commit code → triggers pipelines.

Pipelines build images → training pipelines pick them up.

Training pipelines:

Generate a timestamp,

Launch training jobs on Dev AKS,

If successful, repeat on Prod AKS.

Artifacts and results are stored in Azure Blob Storage.

Excel report scripts call APIs to prepare business-unit–specific reports.

Utility pipelines handle dependencies (install tools, clean images).

Effectively, it ensures that models are retrained quarterly (or on demand), stored properly, and aligned between dev/prod, while Excel reports are generated for different business units automatically.
